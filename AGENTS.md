# AGENTS.md — CYBER-VAULT

Заметка для ИИ-агента, который продолжит работу над проектом. **Прочитай целиком до первой правки.**
Здесь записано не только *что* сделано, но и *почему именно так* — чтобы не задавать одни и те же вопросы заново.

---

## 1. Что это

Локальный диспетчер API-ключей, портативных ИИ-агентов и личных секретов для Windows.
Тёмный интерфейс в стиле Cyber-HUD, работает в системном трее, отдаёт локальный веб-дашборд на `127.0.0.1:17555`.

**Однофайловое приложение.** Весь код — в `app.py`: Python-бэкенд (стандартная библиотека) и весь
интерфейс (HTML + CSS + JS) внутри одной Python-строки. Так сделано ради портативности:
папку можно скопировать на флешку и запустить на другой машине.

| Файл | Роль |
|------|------|
| `app.py` | всё приложение (~130 КБ, ~2600 строк) |
| `start.bat` | лаунчер: чистка → дубликаты → поиск Python → зависимости в `libs\` → старт |
| `vault.json` | хранилище: ключи, агенты, личные секреты (источник правды) |
| `libs\` | локальные зависимости (`pystray`, `pillow`, `pyperclip`), ставится через `pip --target` |
| `backup\` | `vault_*.json` (кольцо из 20 автобекапов) + `app_working_*.py` (ручные копии кода) |
| `notes\` | тексты личных заметок, которые открываются в Блокноте |
| `docs\` | скриншоты для документации |
| `tools\check.py` | единая проверка проекта (статика + эндпоинты + параллельность) |
| `ОПИСАНИЕ.md` / `ОПИСАНИЕ.txt` | пользовательская документация (в `.md` есть скриншот) |

## 2. Команды

```powershell
# запуск
start.bat

# полная проверка (статика + 44 эндпоинта + параллельность) — ЗАПУСКАТЬ ПОСЛЕ КАЖДОЙ ПРАВКИ
python tools\check.py

# только быстрая статика (не трогает vault.json)
python tools\check.py --static

# убрать мусор, если тест был прерван
python tools\check.py --cleanup
```

`tools/check.py` проверяет: компиляцию, pyflakes, `node --check` встроенного JS, отсутствие
вызываемых-но-не-определённых JS-функций, все HTTP-эндпоинты (валидные и битые данные) и
параллельность сервера. Тестовые записи создаёт и удаляет сам.

Приложение стартует **12–15 секунд** (pystray + открытие окна Edge). Не проверяй API раньше.

## 3. Жёсткие правила

1. **Портативность — запрещено писать вне папки проекта.** Зависимости только в `libs\`
   (`pip install --target`), pip-кэш отключён (`--no-cache-dir`), `TMP/TEMP` на время установки
   перенаправляются в `.tmp\` внутри проекта. Глобальный Python не трогать **никогда**.
2. **Всё, что пишется, лежит в папке проекта:** `vault.json`, `libs\`, `backup\`, `notes\`,
   `app.log`, `icon_debug.log`. Экспорт `.env` — только внутрь проекта (см. `export_env_file`).
3. **Единственный источник правды — `vault.json`.** Всё остальное пересобирается из него.
4. **`vault.json` пишется атомарно:** во временный файл с уникальным суффиксом → `os.replace`.
   Так файл физически не может остаться битым. Правки идут под `VAULT_LOCK` (`RLock`).
5. **`HTML_UI` — это Python raw-строка `r"""…"""`.** Вставлять внутрь нельзя `"""` —
   строка оборвётся, и весь остаток HTML станет Python-кодом (SyntaxError). Эта ошибка уже
   случилась: у пользователя был потерян весь хвост `app.py` (сервер, трей, `__main__`).
6. **Не выносить логику в отдельные модули** без явной причины: однофайловность и есть фича.
7. **Перед рискованной правкой** — копия: `copy app.py backup\app_working_<yyyyMMdd-HHMMSS>.py`.

## 4. Архитектура `app.py`

```
1-40        импорты, BASE_DIR, LOCAL_LIBS, sys.path, VAULT_LOCK, глобалы
~140-330    хелперы запуска и иконок: resolve_launch_target, _find_launcher_in_folder,
            extract_exe_icon_png (GDI), backup_vault, provider_signature, resolve_provider_env,
            scan_env_folder
~340-460    class Vault — загрузка/сохранение vault.json (атомарно + бекап)
~470-620    API_PATTERNS (шаблоны распознавания ключей), clipboard_watcher_loop, check_key_health
~700-2100   HTML_UI = r"""…"""   ← весь интерфейс: разметка, стили, JS
~2100-2700  class VaultRequestHandler (do_GET / do_POST), VaultServer, open_window,
            setup_tray_and_run, блок __main__
```

**Фронтенд.** Ванильный JS, без сборки и без фреймворков. Стили — Tailwind с CDN
(`cdn.tailwindcss.com`): **первый запуск требует интернета**, без сети интерфейс будет
нестилизованным, но рабочим. Никаких `fetch` из других origins, сервер слушает только
`127.0.0.1`.

**Состояние на клиенте:** `KEYS`, `APPS`, `PERSONAL`, `REVEALED`, `PING_STATUS`, `AGENT_ICON_CACHE`,
`CURRENT_CAT`. Все списки перерисовываются функцией `renderCurrentView()` — это единственная
точка обновления UI.

## 5. Ключевые решения и почему

| Решение | Почему так |
|---------|-----------|
| `ThreadingHTTPServer` вместо `HTTPServer` | `HTTPServer` однопоточный: один `ping` с таймаутом 5 с блокировал **весь** интерфейс на 5 с (8 пингов = 40 с). После перехода на потоки: 8 пингов = 5 с суммарно, GET во время них — 14 мс |
| `Cache-Control: no-store` на HTML и JSON | Браузер кэшировал старую версию JS → кнопки «не работали» до F5. Это выглядело как баг в коде, но был кэш |
| `VAULT_LOCK` (`threading.RLock`) + уникальный tmp-файл | Потоки могут сохранять `vault.json` одновременно → битый файл или потерянное обновление |
| `webbrowser.open()` только в фоновом потоке (`open_in_browser`) | На этой Windows `webbrowser.open()` **висит дольше двух минут** (проверено отдельным процессом). Раньше `/api/open_url` висел 20+ с и держал HTTP-запрос |
| Иконка агента из самого `.exe` (GDI) | Пользователь просил иконку приложения. Рецепт: `ExtractIconExW` → `GetIconInfo` → `GetObject` → **`GetDIBits` с цветным DC** (`CreateCompatibleDC(GetDC(NULL))` — это 1-битный DC, `GetDIBits` падает с ошибкой 87) → BGRA → PNG base64 |
| `resolve_launch_target` снимает кавычки и ищет `.exe/.bat/.cmd/.lnk` в папке (1 уровень вглубь) | У пользователя путь к WorkBuddy AI хранился в кавычках → `os.path.exists` всегда False; агент — это **папка** (`C:\Apps\ollama-portable` → `ollama-portable\start.bat`), а не файл |
| `.bat/.cmd` запускаются через `cmd /c`, `.exe` — с `cwd` = папка программы | `shell=True` всегда возвращает успех, даже если команды нет → «кнопка не работает» молча. Отсюда честная ошибка «Команда не найдена» |
| Ключи агента уходят в **окружение** запускаемого процесса | Агенты уже привязаны к ключам, но ключи в процесс не передавались — половина фичи «Контроль зависимостей» была мёртвой |
| Ротация: имя переменной — у **первого** ключа группы, значение — у основного, при ⇄ все ключи через запятую | Переключение основного не должно ломать уже настроенные `.env`. OpenRouter принимает `KEY="k1,k2"` и ротирует сам |
| `api()` в JS никогда не бросает исключения | Раньше не-JSON ответ → `res.json()` падал → обработчик молчал, кнопка «не работала». Теперь возвращается `{ok:false,msg}` |
| Вывод лаунчера агента снимается и показывается в модалке | `.bat` отвечает в консоль, которую никто не видит: приложение писало «Запущено» даже когда скрипт ответил «Уже запущено» или «Порт занят». Теперь вывод читается из пайпа, показывается в модалке и дописывается в `launch.log` |
| Автобекап `vault_*.json` после каждого сохранения, кольцо из 20 | `vault.json` — единственная точка отказа. Кольцо с префиксом `vault_` **не трогает** ручные копии `app_working_*.py` |
| `auto-rows-fr` + `h-full` на карточках | Пользователь просил карточки строго одного размера. Цена — пустое место внизу карточек; чтобы его уменьшить, блок ключа `shrink-0`, а список ключей ограничен `max-h-[22rem]` со скроллом |
| `do_POST` разбит на `do_POST` + `_handle_post` | Так весь разбор тела и обработка обёрнуты в `try/except` → JSON-ошибка вместо HTML-трейсбека. **Внимание:** `global CLIPBOARD_MONITOR_ENABLED` объявлен именно в `_handle_post` — при переносе кода туда легко потерять |

## 6. Инварианты (нельзя ломать)

- **JS-функции, на которые ссылается разметка, должны существовать.** Дважды терялись
  (`uniqueEnvName`, `toggleReveal` — второй не был определён вообще, кнопка 👁 не работала
  с самого начала проекта). Ловится проверкой `tools/check.py` → «все onclick-обработчики определены».
- **Список эндпоинтов** (фронт → бэкенд) должен совпадать. Сейчас 23 POST + 4 GET:

  `save_key` `save_app` `save_personal` `delete_key` `delete_app` `delete_personal`
  `ignore_token` `toggle_clip_monitor` `toggle_autostart` `grab_clipboard` `setx` `ping`
  `launch_app` `open_url` `export_env_file` `open_note` `sync_note` `set_primary`
  `set_rotation` `import_env_scan` `import_env_save` `agent_icon`

  GET: `/` `/index` `/api/get_data` `/api/poll_clipboard`

- **Обращения к `body["..."]` запрещены** — только `body.get(...)`. Иначе 500 на кривом запросе.
- **`save_key` требует `env_name` и `value`**, иначе 400 — иначе в базе появляются пустые ключи.
- **Группировка по провайдеру** = `service` + `category` (регистр не важен). По этому же ключу
  считается бейдж `×N`, работает ★/⇄ и собирается `.env`.
- **Имя переменной в `.env`** = `env_name` первого ключа группы. Значение = основной ключ
  (или склейка через запятую при ротации). `_BASE_URL` добавляется автоматически.
- **Агенты запускаются по `path`**, а ключи подставляются по `linked_keys`. `path` может быть
  файлом, папкой или командой PATH.

## 7. Как править `app.py`

Файл большой, правок много. Надёжный порядок:

1. **Сделай копию** `copy app.py backup\app_working_<timestamp>.py`.
2. **Малую правку** (1–5 строк) — инструментом `edit` по уникальному якорю.
3. **Большую замену блока** — питоновский скрипт-сплайс:
   новый блок кладёшь в отдельный UTF-8 файл, скрипт находит начало и конец по строковым
   якорям (`src.index("function renderKeys() {")`) и заменяет. Файл читать и писать с
   `newline=""`, иначе поменяются переводы строк (сейчас в файле **LF**).
   Обязательно `assert` на каждый якорь — иначе замена молча промахнётся.
4. **Прогони `python tools\check.py`** — он поймает и синтаксис, и потерянные функции,
   и сломанные эндпоинты.

> ⚠️ Дважды при такой сплайс-правке терялись JS-функции и хвост файла. Именно поэтому
> `tools/check.py` существует и должен запускаться всегда.

## 8. Грабли на этой машине

| Грабли | Что делать |
|--------|-----------|
| `webbrowser.open()` виснет дольше 2 минут | Только через `open_in_browser()` (фоновый поток) |
| Скриншот встроенного браузера требует видимого окна | Для скриншотов документации — headless Edge: `"<путь к msedge.exe>" --headless=new --disable-gpu --no-sandbox --hide-scrollbars --window-size=1600,1000 --virtual-time-budget=12000 --screenshot="<путь>.png" "http://127.0.0.1:17555/"` |
| Приложение стартует 12–15 с | Не проверять API раньше; в тестах — цикл с повторами |
| Консоль PowerShell в cp1251 — кириллица в выводе ломается | Писать в UTF-8 файл и читать инструментом `read`, либо пользоваться `Out-File -Encoding utf8` |
| Python: `python` / `pythonw` в PATH | `python` доступен в PATH; в глобальном окружении есть `pyflakes` — используй его |
| Google Drive создаёт дубликаты `app (1).py` / `start (1).bat` | `start.bat` переносит их в `backup\` и **не перезаписывает** `app.py` |
| **Путь с обратными слэшами в `onclick` ломается** | В JS-строке `H:\deepseek-harness` превращается в `H:deepseek-harness` (`\d` съедается как escape-последовательность). В разметку передавать **id**, а не путь: `launchAppById('${app.id}')`, а путь брать из `APPS` в JS |
| `scrininfo.exe` без встроенной иконки | Для него и для агентов-команд иконка не извлекается → стоковый эмодзи |

## 9. Что уже реализовано

**Хранилище:** карточки по провайдерам (один провайдер — одна карточка, бейдж `×N`),
маска значения и 👁, копирование ключа с 15-секундной автоочисткой буфера, копирование строки
`.env`, `SetX` в переменные Windows, `Ping` (баланс OpenRouter, имя бота Telegram, статус
Gemini, HTTP-код своего API), поиск, фильтры по группам, табличный вид, ★ основной ключ,
⇄ ротация через запятую, `.env`-сборщик по провайдерам.

**Импорт/экспорт:** импорт `.env` из проекта (сканирование, автоопределение провайдера,
защита от дублей), экспорт `.env` только внутрь папки проекта, перехват буфера обмена
(чистые ключи и блоки `KEY="VALUE"`), личный vault с заметками, открывающимися в Блокноте
(и `⟳` забрать изменения обратно).

**Агенты:** иконка из `.exe` приложения (GDI) со стоковым фолбэком, умный поиск цели
(файл/папка/команда), передача привязанных ключей в окружение процесса, контроль зависимостей
с лампочкой на битом ключе, быстрый запуск из шапки, автозапуск с Windows.

**Надёжность:** атомарная запись хранилища, кольцо автобекапов, потоковый сервер,
`no-store`, защита от 500 на кривых запросах, `pyflakes`/`node --check`/смоук-проверка в
`tools/check.py`, перезапуск иконки трея при падении цикла сообщений, `app.log` рядом с программой.

   и который он выбрал частично: активный ключ + ротация ✅, ключи в окружение агента ✅,
   импорт `.env` ✅, автобекап ✅; оставалось — шифрованный бэкап хранилища
   (заготовка `vault.enc` / `vault.salt` уже лежит в папке, кнопки нет).
